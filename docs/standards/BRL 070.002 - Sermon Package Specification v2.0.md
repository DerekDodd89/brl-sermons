# BRL 070.002 — Sermon Package Specification v2.0

Status: working repository standard, adopted for Phase 1 on 2026-09-07.

This standard applies to newly standardized BRL sermon packages. BRL 070.002 v1.0 remains historical documentation and must not be overwritten. Adoption does not automatically migrate existing packages or authorize content conversion.

## Scope and identity

- Permanent sermon IDs follow the [BRL Sermon ID Standard and Registry](BRL%20Sermon%20ID%20Standard%20and%20Registry.md), adopted 2026-09-13. Preserve existing assignments except explicitly authorized, alias-preserving migrations recorded there. The historical BRL-S070-#### convention is not used for new assignments.
- Preserve existing package directory names and substantive filenames during migration. Record original paths and hashes for provenance.
- The `Derek Dodd Legacy Sermons` and `Josh Hetrick Sermons` directories are protected original-source archives, outside this modern standard. Do not alter their contents or organization.
- Packages live under `sermons/draft/`, `sermons/in-review/`, `sermons/published/`, or `sermons/archived/`. Series indexes reference packages rather than duplicating their content.

## Package structure

```text
<existing-sermon-package>/
├── 00-metadata/
│   └── sermon.json
├── 01-L3-archive/
├── 02-L2-pulpit/
│   ├── 20-minute/
│   ├── 30-minute/
│   └── 40-minute/
├── 03-powerpoint/
├── 04-listener-handouts/
│   ├── elementary/
│   ├── middle-school/
│   ├── high-school/
│   └── adult/
├── 05-supporting-material/
└── README.md
```

This is the allowed layout, not a requirement to create every directory. Only `00-metadata/sermon.json` and `README.md` are mandatory for a draft package. Create content directories only for actual material; create duration and audience subdirectories only when the variants exist. Never create an empty resource or claim availability to fill the layout. Previously existing scaffolding may remain during a no-deletion migration and must be identified as historical.

## Resource roles

- `01-L3-archive`: fullest sermon exposition/archive, including separately authored sections. Preserve each section unless a separately authorized editorial process establishes a combined version. This sermon archive does not replace the originating BRL research archive.
- `02-L2-pulpit`: preaching outlines, with confirmed 20-, 30-, and 40-minute variants in their corresponding folders. Untimed outlines can live directly in this folder; do not guess a duration.
- `03-powerpoint`: PowerPoint files and slide notes. Mockups and drafts must be explicitly labeled in metadata and the README. Presence is not approval.
- `04-listener-handouts`: existing age-specific resources. General or unclassified handouts can live directly here; do not guess the audience.
- `05-supporting-material`: bibliography, notes, artwork, recordings, provenance, and optional rendering references. Use descriptive subdirectories only when needed.
- `README.md`: package guide, inventory summary, gaps, and maintenance notes; JSON is authoritative for machine-readable availability.

Preserve DOCX, PDF, PNG, and other substantive originals. No mandatory Markdown conversion is required. Keep corresponding distribution formats together by resource role rather than duplicating them into a parallel exports tree. Existing outline-page images can remain beside their outline when their precise production role is not established. A later website publishing layer may generate text without replacing source documents.

## Metadata contract

`00-metadata/sermon.json` is UTF-8 JSON. All paths, including provenance destinations, are relative to the package root, not the JSON directory. Use forward slashes.

Required fields: `schemaVersion` ("2.0"), `id` (unchanged existing identity), `title`, `slug`, `status`, `canonicalVersion`, `mainText`, `scriptures`, `series`, `speaker`, `originatingBRLs`, `relatedBRLs`, `review`, `resources`, and `provenance`. Unknown values may be null or empty arrays; never invent approval, authorship, dates, or research links. `canonicalVersion` is the approved sermon content version, independent of schemaVersion; it may be null for an unreviewed draft.

Each resource has a unique `resourceKey`, `role`, `path`, `format`, `version`, `approvalState`, and `sha256`. Include `durationMinutes`, `audience`, and `page` where applicable. `version` may be null when not established. Approval states are `unreviewed`, `unapproved`, and `approved`; mockups additionally use `kind: "mockup"` and `isFinal: false`. Include the original repository-relative path as `originalPath` during migration. Every resource path must exist. Historical metadata can be inventoried as `role: "historical-metadata"` with `authoritative: false`.

Use `availability` to distinguish actual durations/audiences, the existence of presentations, and approval of presentations. Lists of available variants must be derived from existing resources. Use `knownGaps` for missing resources and unresolved information, with no fabricated paths. A resource manifest is not itself doctrinal/editorial approval.

`provenance` records migration date, prior metadata sources, and a mapping report. Historical metadata may contain obsolete availability statements; preserve it while explicitly superseding those statements with the current manifest.

## Naming for new artifacts

Future resources may use `<existing-id>_<title-slug>_<resource>[_<variant>]_v<major>.<minor>.<extension>`. Use descriptive lowercase hyphenated slugs, explicit duration/audience variants, and numbered sections/pages. Do not infer approval from `Final` in a filename. Existing filenames are exempt during Phase 1. New ID assignment and ID-driven package renaming must follow the authoritative ID registry and explicit authorization.

## Publication and verification

Before publication: validate JSON and relative paths, identify approved substantive sermon content, record research provenance or explicitly unassigned links, and complete doctrinal/editorial review. Missing optional duration or audience variants are not publication failures. An unapproved mockup must not be exposed as an approved final presentation.

For migration: capture original artifact paths, sizes, and SHA-256 hashes; move only authorized resources; verify destination hashes; report every old-to-new path, including unchanged historical files. Preserve all substantive artifacts. Do not equate differing formats or variants with duplicates.

## Phase 1 reference and compatibility

The reference implementation is `sermons/draft/BRL-SER-410.003 - The Law of Death, The Grace of Life/`. No other sermon is migrated by this adoption. It has 20- and 30-minute L2 outlines, four audience handouts, and an unapproved presentation mockup. No modern 40-minute folder is created. Historical metadata, folder map, and preexisting empty scaffolding remain to comply with the no-deletion scope.

Compared with v1.0, this version changes metadata placement, replaces generic content/presentation/handout paths with numbered roles, supports multiple variants in a resource list, and removes mandatory `content/outline.md` conversion. Existing consumers of v1.0 paths need an explicit update before consuming v2.0 packages. The v1.0 template remains unchanged in this phase and is not a v2.0 template.
